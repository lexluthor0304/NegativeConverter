# 画像処理性能: 第一段階

## 実装した改善

- 撮影窓の解析結果を、標本の画素バッファ・寸法・片基・色モデル・境界除外・事前彩度・白黒ミックスでキャッシュする。写真や解析設定が変わると再解析する。標本のない通常入力とは別のキーを使う。
- 撮影窓と出力画像で同じ曲線を二度生成しない。最初の自動 WB には引き続き正像標本を渡すが、WB を更新しない調色再描画では標本の正像化自体を省く。
- 大きな 16-bit 画像の片基補償を、従来の乗算・丸め・クリップと全階調で一致する LUT に置換。保持する表は RGB 一組、384 KiB。小さな標本は従来式を使う。
- 自動取景は Worker を先に試す。正常終了（候補なしも含む）なら主スレッド用 OpenCV を初期化しない。Worker が失敗または非対応の場合だけ主スレッド版をロードする。除塵・手動裁切の領域解析は従来どおり必要時にロードする。

出力解像度、色の式、16-bit 精度、自動取景の検出パラメーター、PNG 圧縮設定は変更していない。
返した画像バッファはキャッシュで再利用せず、履歴や Worker 転送で別の画像を書き換えない。

## 固定入力の測定

Apple M1 Pro / Node v26.5.1。ウォームアップ後の 5 回の中央値。合成 16-bit 入力。
初回起動・UI 全体・RAW デコード・ディスク書き出しの所要時間を表す数値ではない。

| 処理 | 変更前 | 変更後 | 備考 |
| --- | ---: | ---: | --- |
| 24 万画素の調色プレビュー | 17.69 ms | 8.04 ms | 約 55% 短縮。変更後は不要な WB 標本描画を省略 |
| 600 万画素の片基補償のみ | 20.85 ms | 11.55 ms | 約 45% 短縮。同じ実行内で旧式と LUT を比較 |
| 600 万画素の変換全体 | 210.92 ms | 209.97 ms | 誤差範囲。全体の高速化とは主張しない |

変換全体では HSL 等を含む LUT 適用後の画素処理が支配的。小段階の短縮を全体の短縮率に読み替えない。

```bash
node scripts/bench-conversion.mjs output/performance-after.json
node scripts/bench-dust.mjs
npm test
npm run test:smoke
npm run build:web
```

変更前の記録: `output/performance-before.json`。
変更後の記録: `output/performance-after.json`。
変更前後の 20 出力（16-bit・8-bit・WB 標本を含む）の SHA-256 が一致。
標本描画を省く経路も、描画する経路と最終画像の SHA-256 が一致する。
キャッシュ試験はカラー・白黒・正像、標準・Frontier・Noritsu、精密曲線、画素の所有権と転送を確認。

検証結果: `npm test` は 45/45 ファイル成功、全 Chrome smoke と Web build も成功。
Chrome では Worker 取景後に主スレッド用 OpenCV が未ロードであることを検証し、
その後に比較用の主スレッド版を明示ロードして検出結果の一致を確認した。
裁切テストは固定 1500ms 待機を廃止し、原寸描画完了後に寸法を厳密照合する。
通常の原寸化は 2500ms アイドル後のため、低解像度プレビューの一時表示を失敗扱いしない。

## 実ファイルの段階測定

`DSC_8800.NEF`（6048 × 4032）を専用 Headless Chrome / CDP で測定。
元ファイルは変更せず、PNG はメモリー中で生成しただけで外部送信・公開していない。
この測定は各 API の単発時間であり、アプリ全体の初回起動時間や速度改善率ではない。
Worker のロードとデータ転送も含む。RAW デコーダーやその既存フォールバックの品質評価ではない。

| 段階 | 実測 |
| --- | ---: |
| RAW プレビュー要求 | 380 ms |
| RAW フル解像度要求 | 322 ms |
| 自動取景: Worker 初回 | 6612 ms |
| 自動取景: 同じ Worker 再使用 | 1376 ms |
| 色解析標本の生成 | 12 ms |
| フル解像度変換 Worker | 1210 ms |
| PNG16 エンコード Worker | 5048 ms / 34.1 MB |

このファイルはプレビュー要求でも同じ画素寸法になるため、半サイズ化の比較として扱わない。
測定記録は `output/performance-nef.json`、診断スクリプトは `output/playwright/processing-performance.mjs`。
疎な除塵マスクの 600 万画素修復は 8.35 ms、空マスクは 6.11 ms、スマートブラシは 5.51 ms。
これらは修復のみで、画像全体の除塵検出の時間ではない。

## 続く改善候補

1. PNG16: 現状は行フィルター None と deflate level 6。ロスレスの行フィルター・ストリーム圧縮を比較し、時間・ピークメモリー・ファイルサイズを同時に評価する。解像度やビット深度の削減で速くしない。
2. 自動取景: Worker は 30 秒アイドルで破棄される。写真間の待ち時間で再初期化するため、バッチセッションに応じた保持・解放を検討する。初期化の重複排除は今回対応済みだが Worker 自体の初回コストは残る。
3. フル解像度変換: 同じ元画像を Worker に毎回コピーする。単一画像の所有権と失効条件を明確にした Worker 内入力キャッシュを検討する。写真数に比例した巨大バッファの保持は避ける。
4. 除塵: 全解像度の検出が主スレッドで動くため、画質を変えず検出と修復を Worker に移す。小さな埃を失う解像度削減は行わない。

コミット・デプロイは行っていない。
