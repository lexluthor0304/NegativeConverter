# 裁切と色解析範囲の分離

## 再現と原因

`DSC_8800.NEF` は複数コマ・端文字・パーフォレーション・フィルム外の領域・遮蔽物を含む。中央のコマを切り抜いた場合と、少し端を残した場合で大きく緑に偏った。

従来の手動裁切は `suggestStep2Mode()` により無条件に `noBorder` を選び、解析用の `coreBorderBuffer` を 0 に変更していた。自動検出が単一コマを確定できなかった場合、残った端・穴も黒白点と WB の計算に入っていた。

## 修正

- 唯一の Studio 画面では裁切状態を理由にエンジンの境界除外値を変更しない。旧画面のモード切り替えに伴う境界除外値の変更処理は削除した。
- 手動裁切時、指定範囲の少し外側まで含めた領域で OpenCV の輪郭／連続エッジを確認する。四辺・画幅比・外側の均一性が揃う場合のみ撮影窓として採用する。
- 検出用画像だけをチャンネルごとに正規化する。出力の RAW、フィルムベース、色変換式には適用しない。
- 確定した撮影窓を元画像の正規化座標で保持。同じコマの留白変更や構図の切り詰めでは維持する。
- 色解析には元画像の撮影窓から最大 25 万画素の共通 16-bit 標本を作る。プレビュー、変換 Worker、個別・一括書き出しが同じ標本を使う。標本から既存エンジンで黒白点・曲線を求め、出力領域全体に適用する。
- 自動 WB も同じ標本の正片を使用。手動 WB や手動グレーポイントを上書きしない。
- 不確かな再検出では以前の解析範囲と WB を保持し、確認を促す。構図の「撮影窓を確認」は既存の裁切枠を再利用するが、出力寸法やフィルムベースを変更しない。キャンセル・取り消し・やり直しに対応する。
- 解析座標は各写真の設定・履歴に保持する。色同期や通常の処理設定同期で、別の写真の解析座標をコピーしない。

フィルムベースの自動推定器自体は今回変更していない。成像領域をフィルムベースとして採取する変更も行っていない。

## 検証

- `analysisRegion.test.mjs`: 直角回転での座標、16-bit 標本、同一コマ／隣接コマの判定。
- `colorAnalysisReference.test.mjs`: カラー／白黒、複数カラーモデルで枠あり・なしの対応画素が一致すること、WB 一致、標本所有権、キャッシュの切り替え。
- `studio-color-analysis-smoke.mjs`: 実ブラウザーでマウス裁切・PNG 書き出しの画素比較、WB の維持、解析範囲確認と取り消し／やり直しで出力寸法が変わらないこと。
- ローカル NEF 検証: `output/playwright/nef-center-frame.png` と `nef-center-with-edge.png`。同一原本から通常のファイル入力・実マウス操作で生成。原本は変更しない。

2026-09-06 の実行結果: `npm test` は 43/43 ファイル成功、`npm run build:web` 成功、`npm run test:smoke` 成功。合成入力の対応領域について、実際に書き出した枠あり・なし PNG の平均画素差は 0。NEF は「最初から端を残す」「撮影窓のみ」「再び端を残す」の順序でも検出に成功し、WB 表示は各ケースで R=1.09 / G=1 / B=1.02 を維持した。

追加の `npm run test:smoke -- --color-analysis-only` も成功。写真の切り替え・再表示後の PNG、および保存済みの写真を一括処理した PNG が単独書き出しと一致することを確認した。

## 制限

複数コマ全体から目的のコマを意味的に推測する機能ではない。指定コマの四辺が隠れている場合や強い遠近変形は確認が必要。被写体や光源に対する色の正解を保証するものではなく、同じ画格で端を残すだけで色が変わる不具合を対象とする。

セッションをまたぐ保存や公開環境へのデプロイは含まない。レンズ補正による幾何変形・周辺減光の出力差まで、留辺の有無で完全一致させる変更ではない。
