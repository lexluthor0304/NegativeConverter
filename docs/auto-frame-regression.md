# 撮影窓の検出回帰

## 検出方針

- 二値化に加えて Canny 輪郭を探索する。閉じた四辺形がない場合だけ、RGB 各チャンネルの線分と直交方向の画素走査を用いる。
- 四辺の対比・支持率・外側の片基色・濃度方向を検証し、隣接画格の反対側の辺や、内部のコマ間スペースを除外する。単なる縦横比の一致では自動適用しない。
- 黒いホルダーの反射縁には少し広いサンプル間隔を使える。ただし四辺の外側がすべて暗く、同じ濃度方向であることを要求し、明るい片基の条件は緩めない。
- HoughLinesP の `CV_32SC4` は OpenCV の版によって N×1 / 1×N になるため、`rows` ではなくデータ長から線分数を計算する。
- 撮影範囲の端に達する不完全なネガ、または同等の複数画格は、規格テンプレートで補完しない。確認必須の結果を返し、自動・一括裁切を止める。
- 写真の色データ、エンジン、原ファイルを変更しない。検出した領域は既存の色解析 ROI と共有し、片辺を出力に残す設定も維持する。

## 通常の回帰

```sh
npm test
npm run build:web
npm run test:smoke
```

`imageWindowDetector.test.mjs` は実 OpenCV で全画幅・正負の傾き・閉輪郭のない画格・隣接コマ・穴・反射縁・不完全な画格・曖昧な複数候補を検証する。`opencvLines.test.mjs` は両方の線分配列形式を検証する。既存ブラウザーテストは自動裁切、色解析の一致、復元、取り消し、一括出力、処理中の UI 応答を確認する。

## ローカル RAW の回帰

原 RAW はリポジトリや外部サービスに送信しない。次のファイルを同じローカルフォルダーに置く。

| ファイル | 期待する動作 |
| --- | --- |
| DSC_4127.NEF | 下辺が撮影範囲外。規格不明・確認必須、全体を保持 |
| DSC_8798.NEF | 隣接コマ・パーフォレーションを除き、中央の 135 画格を裁切・傾き補正 |
| DSC_8800.NEF | 中央の 135 画格を裁切・傾き補正 |
| DSC_8806.NEF | 隣接コマ・パーフォレーションを除き、中央の 135 画格を裁切・傾き補正 |
| _DSC5290.dng | 黒いホルダーと反射縁・端文字を除き、135 画格を裁切・傾き補正 |

```sh
AUTOFRAME_RAW_DIR=/absolute/path/to/raw npm run test:smoke
```

実アプリと同じ RAW デコーダー・Worker で検出した後、通常のファイル入力でも読み込み、画面への自動適用と確認表示を確認する。`output/playwright/raw-autoframe-regression/` に検出枠、Studio のスクリーンショット、JSON を保存する。この出力にも個人写真を含むためコミットしない。

検出枠の検証は、1600 px プレビュー上の目視境界の外接矩形との IoU ≥ 0.94 と各辺の誤差上限を使う。これはサンプルの回帰指標であり、一般的な検出成功率や四隅の厳密な正解データではない。確認必須の 4127 は自動裁切成功数に含めない。
